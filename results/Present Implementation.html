Reading the VoI Results

A plain-English walkthrough of every result in the project so far — what each number is, how it was produced, and which models were used to get there (and why, over the alternatives).

Dataset with results: CWRU Datasets integrated, no results yet: IMS, Paderborn Not integrated: XJTU‑SY, MIMII

What this project actually does

A machine reads vibration from a bearing. Sending every reading to the cloud for close inspection is expensive; ignoring everything risks missing a real fault. This project scores every reading for how worth sending it is — called its Value of Information, or VoI — and uses that score to decide: throw it away, hold onto it, send a short summary, or send the full reading. Today that decision is a policy evaluated on stored data, not a demonstrated physical transmission — no real network or free-space-optical (FSO) link has been simulated yet.

Dataset→ Preprocessing→ CNN→ Novelty→ Uncertainty→ Relevance→ Temporal→ Comm. cost→ VoI→ Decision→ Continual learning

Key termsglossary

CNN
Convolutional Neural Network — an AI model that learns patterns in a raw signal on its own, instead of needing hand-picked rules.
Embedding
A short list of numbers the CNN produces per reading — a compact "fingerprint" used to compare readings.
Novelty
How unfamiliar a reading looks next to a known healthy baseline.
Uncertainty
How unsure the model is about its own prediction.
Task Relevance
How much a predicted condition matters to act on (a fault outranks "normal").
Temporal Importance
How much a reading changed since the previous one.
Communication Cost
How expensive it would be to send this reading to the cloud.
Decision Policy
The fixed rule that turns a VoI score into: Discard, Buffer, Summarize, or Transmit.
Accuracy
Percent of predictions the model got exactly right.
Precision / Recall / F1
Finer-grained scoring than accuracy; F1 balances the two.
Confusion Matrix
A table showing exactly which conditions get mistaken for which.
Parameters
The number of values a model learns during training — roughly, its size.
Leakage-safe
A guarantee that no test data secretly influenced training or tuning.
Continual Learning
Carefully teaching the model a new condition later on, without corrupting what it already knows.

The models we used — and why

Four places in the pipeline involve choosing a model. Where we actually tested alternatives, the numbers are below; where we didn't, that's said plainly too.

Stage · Fault classifier

1D Convolutional Neural Network (custom, compact)

The model used throughout this project: 14,500 parameters, reads the raw 2,048-sample vibration window directly — no hand-picked features. Reaches 100% on its own held-out test set.

Why not a bigger model? A separate edge-vs-cloud experiment (a different, 1,043-sample test split) measured exactly that tradeoff:

Model (separate edge/cloud comparison)Accuracy
Compact edge CNN73.1%
Cloud CNN — 504,580 parameters80.5%

The bigger model wins on raw accuracy. This demonstrates an accuracy–model-size tradeoff — it motivates the need for an information-aware mechanism (like the VoI system built here) that can decide, reading by reading, when the extra processing or communication is actually worth it, rather than always defaulting to one extreme; the comparison itself doesn't prove VoI resolves that tradeoff well, only that the tradeoff is real. The model this project actually runs is kept deliberately simple (no attention layers, no augmentation) so it stays small enough for an edge device, while its 64-number fingerprint (embedding) is reused for free by the Novelty stage below.

100% on the main model's own test set (406 samples) almost certainly reflects how easy CWRU's four conditions are to separate on this clean benchmark — not proof it would generalize to noisier, real-world bearings.

Stage · Novelty detection

Distance-to-healthy-centroid

Measures how far a new reading's fingerprint sits from the average healthy fingerprint.

ModelF1 score
Isolation Forest0.88
One-Class SVM0.94
CNN Autoencoder≈1.00
Distance-to-centroid (chosen for the live pipeline)—

Why this one: in a side-by-side test, the CNN Autoencoder actually scored best. The live VoI pipeline still uses the simpler distance method anyway, because it comes free from the classifier's existing fingerprint — no second model to train, store, or keep in sync — is fully deterministic, and was already accurate enough here. The stronger autoencoder is documented as a promising upgrade, not yet wired into the live pipeline.

Stage · Uncertainty estimation

Entropy of the classifier's own probabilities

No separate model — reuses the numbers the classifier already outputs.

Not tested against alternatives (e.g. Bayesian or ensemble methods) — chosen purely for simplicity, since it needs no retraining.

Why this one: zero extra cost. Its weakness shows up directly in the results: because the classifier is confident almost everywhere, this score ends up nearly flat — which is exactly why it was later down-weighted in the VoI formula (see below).

Stage · Continual learning

Frozen backbone, retrain only the last layer

Keeps the trained classifier's body untouched; only its final 260-number decision layer is retrained on a new condition, gated by a safety check.

Not compared against full-model retraining as an experiment — chosen by design, for a specific safety reason.

Why this one: freezing the body means every existing fingerprint stays mathematically identical after the update — nothing else downstream (novelty reference, stored fingerprints) needs to be redone. Cheaper and safer than retraining the whole model, at the cost of being less flexible about genuinely new signal shapes.

In this canonical order — Novelty, Uncertainty, Relevance, Temporal, Cost — the combined VoI score currently weighs Relevance and Novelty most heavily, Temporal Importance next, Communication Cost a little, and Uncertainty almost not at all (it was too flat to matter).

On held-out test data, this sorts into:

Discard 14.3% Buffer 1.0% Summarize 70.7% Transmit 14.0%

Only Inner Race Fault readings ever reach "Transmit" today. These four labels are the output of the decision policy evaluated on stored data — not a demonstrated physical transmission over a real or simulated communication channel.

v1 → v2Continual learning trial

One full trial: a "new" fault condition was introduced, correctly flagged as unfamiliar, safely admitted as a new known pattern, its last layer retrained, passed its own safety check, and went live as model version 2.

Caveat: CWRU recordings don't actually drift over time, so this proves the mechanism works — not that a real emerging fault has been caught in the wild.

What we can — and can't — conclude

Supported by the evidence

  • The full pipeline works end-to-end on one real dataset.
  • Every stage is reproducible — same seed, same numbers, every time.
  • No test data ever leaked into training or tuning at any stage.

Not yet shown

  • That this generalizes to noisier, real-world bearings or other equipment.
  • That IMS or Paderborn would behave the same way — untested.
  • That the current weights and thresholds are optimal — they're hand-set, not learned.
